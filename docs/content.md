# 双语文案文档 — 核聚变 Flappy 科普小游戏

> 本文档是**所有玩家可见文字的唯一权威来源**(架构文档 §3.4 DRY 的"叶子"之一)。
> 当前支持语言:中文 `zh`、日语 `ja`。
> 初始默认语言为日语 `ja`;右下角圆形"语"按钮在 `zh` / `ja` 间切换。
> `src/content.js` 的 catalog 必须与本文档同步;新增任何玩家可见文字都必须同时提供 `zh` 和 `ja`。
> 配套文档:`architecture.md`(代码组织) / `game-design.md`(玩法与数值)。

## 1. 文案总则

### 1.1 受众与语气
- **受众**:开放日参观者中小学生 + 家长占多数,高中/大学生其次,偶尔同行学者
- **基调**:**热情 + 准确,不卖弄**。能用一句讲清的不写两句
- **避免**:行话堆砌("等离子体动力学不稳定性中的 m=1 模式撕裂特征…")、空泛感叹("好厉害啊!")、说教("你应该知道…")

### 1.2 排版规则
| 规则 | 例 |
|---|---|
| 数字与中文之间留空格 | `47 秒`、`5000 万度`、`完成 3 次聚变` |
| 数字与拉丁文/单位之间留空格 | `13 T`、`400 s`、`ITER` 前后视情况 |
| 标点用全角 | `,。!?:;""''` |
| 大数用万 / 亿,不用百万 / 十亿 | ✅`1 亿度` ❌`100 百万度` |
| 表情符号克制使用 | 仅 HUD 标志(🌡 ⏱ ★)、死亡标题(💥)、聚变特效 |

### 1.3 占位符约定
代码渲染时需要替换:
- `{seconds}` — 本局生存秒数(整数)
- `{temperature}` — 达到的最高温度,人类可读格式("8000 万度" / "1.2 亿度")
- `{fusionCount}` — 完成的聚变次数
- `{score}` — 最终得分
- `{maxCombo}` — 本局达到的最高 combo 数(用于 T4+ 死亡卡片)
- `{ignitionSeconds}` — 进入点火持续期后存活的秒数(0–20,仅 T5/T6 卡片使用)
- `{selfSustained}` — 布尔,玩家是否撑满 20 秒达到自维持(仅 T5/T6 卡片使用)

格式化函数 `formatTemperature(M°)` 的实现规范:
- `< 100` → `{n*10} 万度`(如 30 → "3000 万度")
- `≥ 100` → 中文 `{n/100} 亿度`,日语 `{n/100} 億度`,保留 1 位小数,小数为 0 时省略

### 1.4 双语接口约束
- 所有玩家可见文字只允许出现在 `src/content.js` 的 `CONTENT.zh` / `CONTENT.ja`
- 业务代码只能通过 `t(key)`、`hud.*()`、`getDeathBody()`、`getLearnMorePages()` 等内容接口读取文案
- `src/i18n.js` 在运行时校验 catalog 结构;缺 key、语言不支持、占位符缺值都会抛错
- `npm run build` 会先执行 `npm run check:i18n`;校验失败时 Vite 不会继续打包
- `scripts/check-i18n.mjs` 还会扫描 `src/content.js` 之外的中日文字,防止绕过 catalog 写死文案

## 3. 教程一句话(Menu 上的玩法说明)

```
按 [空格] 触发磁场脉冲,把等离子体悬浮在腔室中央。
撞上炉壁或偏滤器 = 实验失败。
吃 D + T 触发聚变反应。
```

日语:
```
[スペース] で磁場パルスを出し,プラズマを炉心中央に浮かせます。
炉壁やダイバータに触れると実験失敗。
D + T を集めると核融合反応が起きます。
```

三行,允许换行符。短句是关键——参观者不会读长说明。

## 4. HUD 文案与格式

HUD 是 DOM,**视觉化优先**(完整 HUD 设计见 `game-design.md` §10)。本节只列文字模板。

### 4.1 数字字段(模板)
| 字段 | 模板 | 示例 |
|---|---|---|
| 温度 | `🌡 {temperature}` | `🌡 5000 万度` |
| 得分 | `★ {score}` | `★ 47` |
| 时间 | `⏱ {seconds} s` | `⏱ 32 s` |
| He⁴ 累计 | `He⁴ ×{fusionCount}` | `He⁴ ×3` |

### 4.2 燃料舱(左上,视觉化无文字)
**库存由已有燃料图标视觉表达,不显示数字,也不显示灰色空槽**。每行前 3 个正常横排;第 4 个开始半遮堆叠在第 3 个后方,层级从左到右递减,即第 3 个遮住第 4 个、第 4 个遮住第 5 个。文字仅有以下两段:

| Key | 文案 | 触发条件 |
|---|---|---|
| `hud.fuelBay.label` | `燃料舱`(可选,做不做都行) | 一直显示 |
| `hud.fuelBay.fusionReady` | `⚡ 聚变就绪 ⚡` | `collectedD ≥ 1 && collectedT ≥ 1`,聚变触发后立即清除 |

燃料图标弹入、半遮堆叠、聚变就绪的金色脉冲、He⁴ 弹跳计数都由 CSS 动画 + 事件订阅驱动,不需要文字模板。

HUD 不显示障碍数 / collectedD / collectedT 数字(那是内部指标,玩家不应该看到原始数字)。

## 5. 温度里程碑飘字(Canvas 内浮动文字)

由 `TemperatureSystem` 在跨越阈值时发出 `EV.TEMP_MILESTONE`,ParticleSystem 渲染。
**显示位置**:屏幕中部偏上。**显示时间**:1.5 秒淡入淡出。

| 阈值(M°) | 中文 zh | 日语 ja | 备注 |
|---|---|---|---|
| 50 | 已超过太阳核心温度 | 太陽中心温度を超えた | 太阳核心 ≈ 1500 万度,这里夸张到 5000 万好玩家容易够到 |
| 80 | 接近劳森判据下限 | ローソン条件の下限に近づいた | 劳森判据是工程聚变可行性指标 |
| 100 | 达到聚变点火温度! | 核融合点火温度に到達! | **配合金色闪光特效**,本作高潮时刻 |
| 150 | 超越 ITER 设计参数 | ITER の設計値を超えた | ITER 目标约 1.5 亿度 |
| 200 | 已突破现役实验最高纪录 | 現役実験の最高記録を突破 | 现役托卡马克瞬时温度纪录约此区间 |

> **设计意图**:让"太阳核心"和"劳森"这两个名词在玩家头脑里和"游戏中我达到的某个具体温度"绑定。看完游戏一周后还能想起来"哦,5000 万度好像是太阳核心",就成功了。

## 6. 场景元素飘字与拾取反馈

由 ParticleSystem 在 Canvas 内浮现。位置:**屏幕中部偏上**,**显示时间 0.6–0.8 秒淡出**(里程碑除外,见 §5)。

### 6.1 MHD 不稳定区(InstabilityRegion)生成时
障碍名称三选一随机(0.8 秒淡出):

| 名称 | 现实物理对应 |
|---|---|
| 撕裂模 | Tearing mode,磁岛形成 |
| 气球模 | Ballooning mode,曲率驱动 |
| 锯齿模 | Sawtooth oscillation,芯部反演 |

普通参观者读到名字就当作"哦原来这种叫撕裂模",同行看到会会心一笑。

偏滤器(Divertor)**不显示飘字**,作为"水管"是默认障碍,频繁飘字反而干扰玩感。

### 6.2 锂-6(⁶Li)拾取
拾取瞬间屏幕中部飘字(0.6 秒淡出,紫银色):
```
⁶Li → T 增殖
+2
```
**意图**:让玩家明白"刚才那个紫的不是普通氚,是通过锂增殖出来的"。一次飘字承担科普 + 计分两个反馈。

### 6.3 钨碎片(TungstenDebris)撞击
撞击瞬间屏幕中部飘字(0.6 秒淡出,冷灰白色):
```
钨杂质溅射
等离子体冷却 −1 档
```
配合屏幕 0.3 秒红闪 + 等离子体短暂闪烁。
**注意**:钨碎片**不致死**,飘字语气是"被冷却"而不是"实验中断",玩家应能感受到"还能玩,只是退步"。

### 6.4 NBI 中性束(NeutralBeamInjection)穿过
等离子体接触加成带瞬间飘字(0.6 秒淡出,洋红 → 金色渐变):
```
中性束加热!
+1 档
```
配合等离子体 0.5 秒金光高亮 + 通道淡出。

### 6.5 自由电子粒子擦过(GDD §5.6)
擦过单个粒子时,**不出文字飘字**,只出一个**纯视觉的"+1"小数字飞字**(20 px,青白 `#aaffff`,0.4 秒向上飘 30 px 同时淡出)。
- 多个粒子连续擦过 = 多个 `+1` 阶梯飘起(每个 y 偏移 ±8 px,避免重叠)
- **不进入 fuel bay,不进入 combo,不出科普文字** — 它的全部存在意义是"持续小反馈",任何文字都会冲淡这个用途
- 配音(二期):极轻的 "嗒" 短音(20 ms),不超过聚变音的 1/10 响度

### 6.6 配色对照
| 飘字 | 主色 | 用意 |
|---|---|---|
| 不稳定区名称 | 红橙 #ff5544 | 警告/危险 |
| Li-6 增殖 | 紫银 #cc88ff | 稀有/赚到 |
| 钨碎片 | 冷灰白 #ccd0d8 | 工业事故感 |
| NBI 加热 | 洋红 → 金 渐变 | 能量奖励 |
| 自由电子 +1 | 青白 #aaffff | 持续微反馈,不抢戏 |
| Combo ×2 ~ ×5 | 黄 → 橙 → 红 → 洋红 → 白热 | 升级感(详 §7.2) |
| 阶段切换名 | 阶段 glow 主色 | 与背景辉光一致 |
| 自维持成功 | 金 #ffcc44 + 白热高光 | 终极成就 |
| 温度里程碑(§5) | 各档独立色 | 与里程碑色一致 |

## 7. 聚变特效、Combo 与高潮反馈

> 本作的"爽感"几乎全在这一章。文字本身只是骨架,**真正动人的是动画时间轴**:每一帧 scale、位置、透明度、辉光的精确编排。
> 实现者(代码 / AI coding 后续会话)必须严格按本章动画规范实现,不要"差不多"。

### 7.1 单次聚变粒子标签(基础)

聚变事件触发时(combo=1),2 个粒子飞出,各带文字标签:

| 粒子 | 标签 | 颜色 | 路径 | 字号 | 持续 |
|---|---|---|---|---|---|
| He⁴ 核 | `He⁴` | 红色 `#ff4444` | 左下,初速 (-180, 120) px/s,带重力 | 22 px 粗体 | 1.5 s 淡出 |
| 中子 | `n` | 白色 `#ffffff` | 右上,初速 (180, -100) px/s | 22 px 粗体 | 1.5 s 淡出 |

**不写"氦 4"** —— 化学符号比中文更有"反应方程式"的视觉冲击。

### 7.2 Combo 飘字 — 动感与质感规范(本节重点)

> 这是整局视觉反馈的"爆点"。**字越大、色越烈、画面越震,玩家会本能地想再来一次**。

#### 7.2.1 文字模板(双语必须同步)

| comboCount | zh 文字 | ja 文字 | 备注 |
|---|---|---|---|
| 1 | `He⁴  +5` | `He⁴  +5` | 不显示 "COMBO",视为单次聚变 |
| 2 | `⚡ COMBO ×2   +10` | `⚡ COMBO ×2   +10` | "COMBO" 是国际通用游戏术语,不翻 |
| 3 | `⚡⚡ COMBO ×3   +25` | `⚡⚡ COMBO ×3   +25` | |
| 4 | `⚡⚡⚡ COMBO ×4   +50` | `⚡⚡⚡ COMBO ×4   +50` | |
| 5+ | `⚡⚡⚡⚡ MAX COMBO   +100` | `⚡⚡⚡⚡ MAX COMBO   +100` | ×6 以上固定显示 MAX,数字不变 |

字符间 `+N` 前留 3 个全角空格(`   `)拉开视觉节奏,**不要紧贴**。

#### 7.2.2 视觉规格(字号 / 颜色 / 字体)

| combo | 字号 | 主色 | 描边 | 发光(shadowBlur/Color) | 字重 |
|---|---|---|---|---|---|
| 1 | 28 px | `#ffcc44` 金 | 黑 1 px | 8 px / `#ffcc44` | 800 |
| 2 | 36 px | `#ff8844` 橙 | 黑 1.5 px | 12 px / `#ff8844` | 800 |
| 3 | 44 px | `#ff4477` 红 | 黑 2 px | 16 px / `#ff4477` | 900 |
| 4 | 56 px | `#ff44dd` 洋红 | 黑 2 px | 22 px / `#ff44dd` | 900 |
| 5+ | 72 px | 白热 `#ffffff` | `#ff44dd` 4 px 主色描边 | 30 px / `#ffffff` + 二次 18 px / `#ffcc44` | 900 |

**字体栈**(粗体 display 字体,而非等宽):
```
'Inter', 'Space Grotesk', 'Noto Sans SC', 'Noto Sans JP',
'PingFang SC', 'Hiragino Sans', system-ui, sans-serif
```

`letter-spacing: 0.02em`,**不要斜体**。等宽字号大了缺张力,务必用 display sans。

#### 7.2.3 入场 → 停留 → 出场 动画时间轴

每条 Combo 飘字总寿命 **1.35 秒**,分三段。所有缓动函数用 `easeOutBack`(过冲)和 `easeInQuad`(淡出)。

| 时间 (s) | 行为 |
|---|---|
| 0.00 | 在等离子体光球位置生成,初始 `scale = 0.4`、`alpha = 0`、`y = plasma.y` |
| 0.00 → 0.08 | **猛烈过冲**:`scale` 从 0.4 → 表中的过冲倍率(combo×1: 1.15;×2: 1.20;×3: 1.25;×4: 1.30;×5+: 1.40),`alpha` → 1.0,easeOutBack |
| 0.08 → 0.16 | **回弹**:`scale` 回到 1.0,easeOutQuad |
| 0.16 → 0.85 | **停留呼吸**:`scale` 在 1.0 ± 0.04 范围低频抖动(2 Hz 正弦),`alpha = 1`,位置静止 |
| 0.85 → 1.35 | **上浮淡出**:`y` 向上飘 80 px(easeOutCubic),`scale` → 0.95,`alpha` → 0(easeInQuad) |
| 1.35 | 销毁 |

> 关键点:**过冲是"动感"的来源**。没有过冲的飘字会感觉是 PPT 切片;过冲过头(>1.5)又显得廉价。1.15–1.40 区间是甜点。

#### 7.2.4 屏幕级反馈(超过文字本身的部分)

字越大,屏幕越参与。这是"质感"的来源。

| combo | 屏幕级反馈 | 触发时机 |
|---|---|---|
| 1 | — | 单次聚变本身已有特效,不重复 |
| 2 | 屏幕四角金色辉光淡入 0.15 s → 淡出 0.3 s,峰值 alpha 40% | combo 命中瞬间 |
| 3 | 同 ×2 + 全屏 radialGradient 金光脉冲 1 次(0.25 s,峰值 alpha 25%) | 命中瞬间 |
| 4 | 同 ×3 + 屏幕边缘横向震颤 0.10 s(camera shake amplitude 3 px,decay) | 命中瞬间 |
| 5+ | 同 ×4 + **全屏白闪一帧**(0.05 s,峰值 alpha 8%,不要更高,刺眼)+ 震颤延长到 0.20 s + 边缘金色 vignette 持续到飘字消失 | 命中瞬间 |

> ⚠️ **白闪与震颤是"质感"的最后一块**,但**必须克制**:
> - 白闪 alpha **不能 ≥ 10%**(展位环境下家长会皱眉)
> - 震颤 amplitude **不能 ≥ 5 px**(玩家会觉得画面在抖动,影响避障)
> - 5 秒内累计闪烁次数 **不能 > 4 次**(光敏 / 眩晕风险)
>
> 这些数字写进 `config.combo.screenFx`,不要硬编码。

#### 7.2.5 与 Combo 计时圆环(HUD §10.7)的关系

每次新的 combo 命中,HUD 圆环要做两件事:
1. **同步切色**:外圈颜色立即切到本档 combo 颜色(与飘字主色同步),0 ms 过渡
2. **弹性回弹**:圆环 `scale` 1.0 → 1.4 → 1.0,0.25 s,easeOutBack
3. 圆心数字弹跳:`scale` 1.0 → 1.6 → 1.0,0.20 s

#### 7.2.6 失败 / 重置反馈
combo 计时到期(玩家没接上)、玩家死亡、阶段切换出 IGNITION_BURST 时,combo 重置:
- HUD 圆环灰化 0.15 s 后淡出(`grayscale(1)` + `opacity 0`)
- **不出飘字**(失败不需要被通知,沉默就是反馈)

### 7.3 阶段切换提示(GDD §7.4)

每次跨越温度阶段阈值,屏幕中部偏上短暂飘大字,通知玩家"局面变了"。

#### 7.3.1 文字模板

| Phase | zh 大字 | ja 大字 | zh 副标题(小字) | ja 副标题 |
|---|---|---|---|---|
| `IGNITION_PREP` | 启动 | 起動 | — (无,游戏开局就是这阶段) | — |
| `HEATING` | 主动加热 | 加熱開始 | 偏滤器变频繁,小心钨碎片 | ダイバータ密集,タングステン注意 |
| `CRITICAL` | 临界点 | 臨界点 | 接近 1 亿度 —— 准备点火 | 1 億度に接近 —— 点火準備 |
| `IGNITION_BURST` | 点火成功 | 点火成功 | (合并到 §7.4 进入大字,不重复显示这条) | — |
| `RECORD` | 突破纪录 | 記録更新 | 现役实验最高区间 —— 表演时间 | 現役最高領域 —— 自由演舞 |

#### 7.3.2 动画规格

- 大字:60 px,字重 900,字体栈同 §7.2.2,主色 = 阶段 `glow` 色
- 位置:水平居中,垂直 30% 处(略高于画面中心)
- 副标题:22 px,字重 600,白色 alpha 0.85,在大字下方 16 px 处
- 总寿命 1.8 s:淡入 0.25 → 停 1.20 → 淡出 0.35
- 大字入场:`scale 1.10 → 1.00` easeOutBack(轻过冲,不像 combo 那么猛)
- 出场:`scale 1.00 → 0.95`,`y` 不动

### 7.4 点火高潮相文案(GDD §7.5)

#### 7.4.1 进入瞬间(0–1.5 秒)

屏幕中央巨大双行飘字:

| 行 | zh | ja | 字号 | 主色 |

### 8.1 死因标题(根据死亡类型)

|---|---|

| 撞偏滤器 | 偏滤器板汽化 |

### 8.2 科普段落(根据本局达到的最高温度)

> 实现规范:`getDeathBody(maxTemp)` 返回对应文案。**取严格小于的最大档位**(例如 maxTemp=100 走 T5 而非 T4)。

**T1 — `maxTemp < 30`(典型 0–10 秒就死)**
```
等离子体非常脆弱——哪怕是最初的 1000 万度,
也已经把任何固体材料瞬间汽化。
这就是为什么我们需要磁场把它"悬空"住,
让它一刻都不接触炉壁。
```

**T2 — `30 ≤ maxTemp < 50`**
```
不错的开局!你已经把等离子体加热到了 {temperature}。
作为参考:太阳核心约 1500 万度,
你已经远远超过它了——只是比起聚变反应需要的温度
还差一些。
```

**T3 — `50 ≤ maxTemp < 80`**
```
{temperature} —— 你已经超过太阳核心了。
但要让氘氚发生足够多的聚变反应,
人类需要的是太阳核心 5–10 倍的温度。
原因很简单:地球上没有太阳那样的引力压力,
我们只能靠"更高温度"来弥补。
```

**T4 — `80 ≤ maxTemp < 100`**
```
{temperature} —— 你触到了"劳森判据"的门口。
这是工程上判断聚变能否净产能的指标:
温度、密度、约束时间三者乘积要够大。
你已经搞定了温度,真实的 ITER 还得搞定后两个。
```

**T5 — `100 ≤ maxTemp < 150`(高潮档位)**
```
🎉 {temperature} —— 你点火了!

聚变点火温度是 1 亿度。这是地球上人为创造的
最极端环境之一。
你坚持了 {seconds} 秒、完成了 {fusionCount} 次聚变,
最高 COMBO ×{maxCombo}。
现实中 ITER 的目标是稳定维持 400 秒以上。

{ignitionLine}
```

`{ignitionLine}` 的三种取值(由代码根据 `selfSustained` 和 `ignitionSeconds` 选择):
- `selfSustained == true` →
  `你撑满了 20 秒 —— 一次自维持燃烧。`
  `现实中目前没有任何托卡马克达到过这一点。`
- `selfSustained == false && ignitionSeconds > 0` →
  `你在点火持续期内撑了 {ignitionSeconds} 秒,差一点就自维持了。`
- `ignitionSeconds == 0`(刚点火就死) →
  (空字符串,不渲染这行)

**T6 — `maxTemp ≥ 150`**
```
{temperature} —— 已经超越 ITER 的设计参数了。
你大概是研究室的人,或者天赋异禀。

{ignitionLine}

我们办公室在 3 楼,欢迎来聊。
```

T6 的 `{ignitionLine}` 逻辑同 T5(只是位置不同)。
